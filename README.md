# XYZ AI School Assistant

A FastAPI-based AI school assistant. Supports role-based school actions
(attendance, timetables, class schedule) and a general-purpose educational
`/ask` endpoint backed by a real, swappable AI service abstraction — not a
fixed lookup table of hardcoded question/answer pairs.

## Features

- Role-based access control (student / parent / teacher / principal)
- Attendance: own attendance (student), child's attendance (parent),
  attendance trend and school-wide analytics (teacher/principal)
- Timetable and class schedule lookups
- `/ask`: general educational Q&A answered by an AI service abstraction
  (`services/ai_service.py`) — works for **any** question, including ones
  never referenced anywhere in the source code
- Conversation history per role/student, so follow-up questions have context
- Role-specific AI personas (friendly student assistant, caring parent
  assistant, professional teacher/principal assistant)
- Language selection across the 11 languages required by the spec
- `/escalate`: mock "talk to a teacher / contact school management" flow —
  only reports success if the mock request actually succeeds, and always
  asks for confirmation first
- Centralized error handling: no stack traces or internal details are ever
  returned to the client
- Full pytest suite covering behavior and API contracts (not one hardcoded
  expected sentence)

## Environment Variables

None are required to run the app or the tests — with no `AI_API_KEY` set,
`/ask` automatically falls back to an offline mock AI provider so the app
and test suite work without any external credentials.

| Variable          | Required | Default                          | Purpose                                   |
|--------------------|:--------:|-----------------------------------|--------------------------------------------|
| `AI_API_KEY`       | No       | *(unset → mock provider is used)* | API key for a real, OpenAI-compatible chat-completions endpoint |
| `AI_API_BASE_URL`  | No       | `https://api.openai.com/v1`       | Base URL of the AI provider                |
| `AI_MODEL`         | No       | `gpt-4o-mini`                     | Model name to use                          |
| `AI_TIMEOUT_SECS`  | No       | `20`                              | Request timeout for the AI provider        |

Create a `.env` file (already git-ignored) if you want to set these locally:

```
AI_API_KEY=sk-...
AI_API_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
```

**Without `AI_API_KEY` set**, `/ask` still returns a 200 with a real,
question-specific response — it's just generated by the offline mock
provider (clearly labeled `[MOCK AI]` in the answer) rather than a live
LLM. This is intentional: it keeps the app and test suite fully functional
without requiring a paid API key, while making it obvious in the response
when you're not talking to a real model.

## API Usage

### `POST /ask`

```json
{
  "question": "What is Ohm's Law?",
  "role": "student",
  "student_name": "Rakshita",
  "requested_student": "Rakshita",
  "language": "english"
}
```

Response:

```json
{
  "question": "What is Ohm's Law?",
  "role": "student",
  "language": "english",
  "answer": "..."
}
```

`role` accepts `student`, `parent`, `teacher`, `principal`.
`language` accepts english, hindi, tamil, telugu, marathi, bengali,
gujarati, punjabi, kannada, malayalam, urdu (defaults to `english`).

School-action questions are routed to the relevant mock service
(e.g. `"What is my attendance?"`, `"What is the class schedule?"`,
`"What is the overall school attendance?"`); anything else is answered by
the AI service.

### `POST /escalate`

```json
{
  "role": "parent",
  "student_name": "Rahul",
  "target": "teacher",
  "confirm": false
}
```

First call (with `confirm: false`) returns a confirmation prompt. Call
again with `confirm: true` to actually submit the mock request:

```json
{
  "status": "submitted",
  "message": "Your call request has been submitted to the teacher.",
  "request_id": "..."
}
```

`target` accepts `teacher` or `school_management`.

### `GET /health`

Returns `{"status": "healthy"}`.

## Known Limitations / Not Implemented

The full assessment describes a broader product (chat UI, AI avatar with
voice/lip-sync, live translation, real teacher-notification integrations)
than a backend API assessment can reasonably cover. This implementation
provides the backend logic, mock integrations, and API contracts for all
of those flows, but does not include:

- An actual chat/voice front-end or AI avatar (out of scope for a FastAPI
  backend; would be a separate client application)
- Real speech-to-text / text-to-speech
- Real translation into the 11 supported languages when using the mock AI
  provider (the real provider is instructed to answer in the requested
  language, but this requires a configured `AI_API_KEY` to verify)
- A real teacher/school-management notification system (mocked, as the
  assessment explicitly allows)
